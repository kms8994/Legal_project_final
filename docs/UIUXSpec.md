# UI/UX 명세

## 1. UX 목표

CaseLens의 UX는 사용자가 판례를 빠르게 찾고, 비교할 판례를 고르고, 결과가 갈린 이유를 이해하도록 돕는 데 집중한다. 장식적인 랜딩 페이지보다 실제 검색 경험이 첫 화면에 있어야 한다.

## 2. 정보 우선순위

### 검색 결과 카드

1. 사건번호, 법원, 선고일
2. 사건명과 도메인
3. 사실관계 요약
4. 주요 조문
5. 결과 방향과 key factor
6. 원문 근거
7. 기준 판례 선택

### 비교 후보 카드

1. 기준 판례와 공통되는 사실관계
2. material facts 일치도
3. 미세 차이 후보
4. 결과 차이
5. 비교하기

### 비교 분석 화면

1. 공통 사실관계
2. 핵심 미세 차이
3. 결과 차이
4. 원문 근거
5. 피드백

## 3. 화면별 UX

### 검색 시작

- 검색창을 중심에 둔다.
- 조문/자연어/사건번호 탭을 제공한다.
- 사용자에게 긴 사용법을 설명하지 않는다.
- 예시 placeholder로 입력 방식을 암시한다.

### 검색 결과

- 결과 카드에는 AI 요약과 공식 원문 링크를 함께 둔다.
- 자연어 검색의 경우 `이렇게 이해했어요` 패널을 제공한다.
- 사용자가 기준 판례를 고르면 다음 단계가 명확히 보인다.

### 비교 후보

- 후보를 단순 목록으로 보여주지 않는다.
- 왜 이 판례가 비교 후보인지 보여준다.
- 사실관계 유사성과 결과 차이를 분리해서 보여준다.
- outcome 차이가 있지만 사실관계 유사도가 낮은 후보는 낮게 표시한다.

### 비교 분석

- 나란히 비교가 기본이다.
- 모바일에서는 탭 또는 세로 스택으로 전환한다.
- turning point는 별도 섹션으로 강조한다.
- 각 주장에는 근거 문단으로 이동하는 링크를 둔다.

## 4. 비교 UI 구성

```text
[기준 판례]  [비교 판례]

공통 사실관계
- 둘 다 차량 대 보행자 사고
- 둘 다 손해배상 범위가 문제됨

핵심 미세 차이
1. 피해자 행위
   기준: 과실 낮게 인정
   비교: 무단횡단 인정
   의미: 과실상계 비율 차이

결과 차이
기준: 일부 인용
비교: 과실상계로 감액

원문 근거
[p12] [p18] [p22]
```

## 5. 예외 UX

| 상황 | UX |
|------|----|
| 조문 파싱 실패 | 입력 예시와 후보 법령 표시 |
| 조문 검색 0건 | 인접 조문, 자연어 검색 제안 |
| 자연어 confidence 낮음 | 추가 질문 1개만 표시 |
| 비교 후보 부족 | 조건 완화 단계와 이유 표시 |
| LLM timeout | 구조화 표 기반 fallback 표시 |
| evidence 부족 | 근거 부족 배지 표시 |
| 구조화 검수 전 | 검수 전 요약 배지 표시 |

## 6. 법률 고지 UX

표시 위치:

- 첫 화면 하단 짧은 고지
- 결과 카드의 AI 요약 배지
- 비교 분석 하단 전문 고지
- 공식 원문 링크 옆 확인 버튼

## 7. 접근성

- 키보드로 검색, 카드 선택, 비교 이동 가능
- 색상만으로 결과 차이를 표현하지 않음
- 결과/차이/근거를 텍스트로 제공
- 모바일에서 표가 잘리지 않도록 카드형 비교로 전환
- 버튼 텍스트는 동작 중심으로 작성

## 8. 완료 체크리스트

- [ ] 첫 화면에서 바로 검색 가능하다.
- [ ] 비교 후보의 추천 이유가 보인다.
- [ ] 미세 차이와 결과 차이가 구분된다.
- [ ] 원문 근거로 이동할 수 있다.
- [ ] 모바일 비교 화면이 사용 가능하다.
- [ ] 예외 상태가 막다른 길이 아니다.
