# CaseLens PRD

## 1. 제품 개요

CaseLens는 사용자가 법조문, 자연어 사건 설명, 사건번호를 입력하면 관련 판례를 찾고, 기준 판례와 비교 판례의 사실관계, 쟁점, 결과 차이를 교육적으로 확인할 수 있게 하는 판례 검색 및 비교 서비스다.

MVP의 핵심은 단순히 많은 판례를 보여주는 것이 아니라, **논리적으로 유사한 사실관계를 가진 판례들을 비교하고, 사소하지만 법적으로 중요한 차이가 결과를 어떻게 갈랐는지 보여주는 것**이다.

## 2. 목표 사용자

1. 법학 전공 학생
2. 로스쿨생
3. 판례 비교 학습이 필요한 수험생
4. 법률 리서치를 빠르게 시작하려는 일반 사용자

MVP에서는 법률 전문가용 고급 리서치 플랫폼보다 학습자 중심의 비교 도구를 우선한다.

## 3. 사용자 문제

사용자는 판례를 검색할 수는 있지만 다음 문제가 있다.

- 같은 조문을 다룬 판례가 너무 많아 어떤 판례를 먼저 봐야 할지 어렵다.
- 사실관계가 비슷한 판례끼리 비교하기 어렵다.
- 결론이 왜 달라졌는지 파악하려면 원문을 오래 읽어야 한다.
- 판례 결과가 다른 이유가 사소한 사실 하나인 경우 이를 놓치기 쉽다.

## 4. 핵심 가치

CaseLens는 다음 세 가지 가치를 제공해야 한다.

1. 조문 기준 판례 검색
2. 자연어 사건 설명 기반 유사 판례 검색
3. 기준 판례와 사실관계가 최대한 유사하지만 결과 또는 판단 강도가 다른 판례 비교

## 5. MVP 범위

### 포함

- 손해배상 중심 도메인
- 핵심 조문 15~30개
- 샘플 판례 300~500건
- 조문 검색
- 자연어 검색
- 기준 판례 선택
- 비교 후보 Top 5 추천
- 판례 상세 화면
- RAG 기반 판례 카드 요약
- RAG 기반 두 판례 비교 분석
- 원문 근거 문단 표시
- 검색/비교 피드백 저장
- 구조화 confidence 및 needs_review 표시
- 기본 rate limit
- 법률 자문 아님 고지

### 제외

- 결제와 구독
- Elasticsearch 운영
- Qdrant 분리 운영
- Redis 필수 캐시
- Airflow
- 전체 법률 도메인
- 전체 하급심 판례 수집
- 대규모 관리자 검수 UI
- 실시간 법률 자문 답변
- 승소 가능성 예측

## 6. MVP 도메인

초기 도메인은 손해배상으로 고정한다.

우선 세부 주제:

- 불법행위 책임
- 교통사고
- 과실상계
- 위자료
- 사용자책임
- 공동불법행위
- 손해배상 범위

초기 조문 후보:

- 민법 제393조
- 민법 제396조
- 민법 제750조
- 민법 제751조
- 민법 제756조
- 민법 제760조
- 민법 제763조
- 자동차손해배상 보장법 제3조

최초 MVP에서는 이 목록에서 시작하고, 데이터 수집 결과에 따라 15~30개로 확장한다.

## 7. 핵심 사용자 흐름

### 조문 검색 흐름

```text
사용자 조문 입력
→ 조문 정규화
→ 내부 법령/조문 DB 검증
→ 해당 조문 인용 판례 검색
→ 판례 카드 표시
→ 기준 판례 선택
→ 비교 후보 추천
→ 비교 화면 표시
```

법령정보센터 API는 런타임 검색 중 호출하지 않는다. 사전에 로컬/배치 파이프라인으로 법령, 조문, 판례를 DB에 적재한다.

### 자연어 검색 흐름

```text
사용자 사건 설명 입력
→ LLM intent parsing
→ 추정 조문 법령 DB 검증
→ hybrid retrieval
→ 관련 판례 카드 표시
→ 기준 판례 선택
→ 비교 후보 추천
```

### 비교 흐름

```text
기준 판례 선택
→ 사실관계 유사 후보 검색
→ material facts 정밀 재랭킹
→ 결과가 다른 후보 우선 표시
→ 두 판례의 공통 사실, 미세 차이, 결과 차이 표시
→ 원문 근거 문단 연결
```

## 8. 비교 기능 원칙

비교 후보 추천의 우선순위는 다음과 같다.

1. 사실관계가 논리적으로 매우 유사한가
2. material facts가 유사한가
3. 같은 법률 도메인과 사건 유형인가
4. 같은 쟁점 또는 같은 조문을 다루는가
5. 결과 또는 판단 강도가 다른가
6. 결과를 가른 미세 차이를 설명할 근거 문단이 있는가

결과가 다르다는 조건은 중요하지만, 사실관계가 덜 유사한 판례를 위로 올리는 이유가 되면 안 된다.

## 9. RAG 원칙

CaseLens의 RAG는 일반 챗봇이 아니라 판례 검색과 비교를 보조하는 구조다.

```text
검색 후보 찾기
→ 근거 문단 가져오기
→ 유사도와 대비도 계산
→ LLM이 근거 안에서만 요약과 비교 설명 생성
```

LLM은 다음을 하면 안 된다.

- 원문에 없는 사실 생성
- 존재하지 않는 조문 생성
- 법률 결론 단정
- 승소 가능성 수치화
- 최신 법령 확인 없이 단정

## 10. 성공 기준

| 항목 | MVP 목표 |
|------|----------|
| 데이터 수집 | 손해배상 판례 300~500건 |
| 조문 검색 | precision@10 0.80 이상 |
| 자연어 검색 | Top-5 관련 판례 평균 3건 이상 |
| 비교 후보 | Top-5 중 사실관계 유사 후보 평균 3건 이상 |
| 결과 차이 | Top-5 중 결과 또는 판단 강도 차이 후보 평균 2건 이상 |
| 구조화 | facts, issue, material_facts, outcome 정확도 0.75 이상 |
| 근거 연결 | 사용자 노출 요약의 evidence span 연결률 90% 이상 |
| 속도 | 검색 p95 2.5초 이하 |
| 비교 생성 | LLM 성공 시 10초 이내, 실패 시 fallback 표시 |
| UI | 검색 시작에서 비교 결과까지 3클릭 이내 |

## 11. 법률 고지

서비스 전역에 다음 취지가 표시되어야 한다.

```text
CaseLens의 검색 결과, AI 요약, 판례 비교 분석은 참고용 정보입니다.
법률적 판단이나 실제 사건 대응은 반드시 판례 원문, 최신 법령, 전문가 검토를 통해 확인해야 합니다.
본 서비스는 판례 데이터 누락, AI 요약 오류, 법령 개정 미반영 가능성을 포함합니다.
```

## 12. MVP 완료 정의

MVP는 다음 조건을 만족하면 완료로 본다.

- 조문 검색, 자연어 검색, 기준 판례 선택, 비교 후보 추천, 비교 분석 화면이 end-to-end로 동작한다.
- 모든 AI 요약과 비교 설명은 evidence span을 가진다.
- LLM 실패 시 구조화 데이터 기반 fallback 비교 화면이 나온다.
- 검색/비교 피드백이 저장된다.
- 평가 세트를 실행해 목표 지표를 확인할 수 있다.
- 원문 전체 대체가 아니라 공식 링크와 근거 문단 중심으로 표시된다.
